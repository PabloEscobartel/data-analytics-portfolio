## 1. Реализованные улучшения

### 1.1 [BUG-11] Кнопка "Сложно" с автоматической декомпозицией задач

**Проблема:** Пользователи (особенно персона P1 - прокрастинатор) сталкивались с задачами, которые казались слишком большими и абстрактными. Единственным действием была кнопка "Done", что не помогало справиться с прокрастинацией.

**Решение:**
Добавлена кнопка "😣 Сложно", которая автоматически разбивает задачу на 2-3 более мелких шага с помощью LLM. Исходная задача помечается как выполненная, а новые подзадачи добавляются в список.

**Реализация:**
```python
@app.post("/task/{task_id}/hard")
async def task_hard(task_id: int):
    db = SessionLocal()
    task = db.query(Task).filter(Task.id == task_id).first()
    if task:
        decomp = RAGService.decompose_task(task.title)
        if decomp and "subtasks" in decomp:
            for st in decomp['subtasks']:
                new_task = Task(
                    project_id=task.project_id, 
                    title=st.get("title"), 
                    minutes=st.get("minutes", 15)
                )
                db.add(new_task)
            task.status = "done"
            db.commit()
    db.close()
    return RedirectResponse(url="/?msg=Task+simplified", status_code=303)
```

**Результат:** Пользователи получили инструмент для преодоления "паралича перед большой задачей". Это снижает порог входа в работу.

### 1.2 [BUG-10] Устойчивый парсинг JSON-ответов LLM

**Проблема:** LLM иногда возвращал JSON с дополнительным текстом вокруг ("Вот ваш план: {...}"), что приводило к crash при вызове `json.loads()`.

**Решение:**
Реализована функция `extract_json_from_string()` с многоуровневой стратегией парсинга:
1. Попытка прямого парсинга
2. Извлечение JSON через regex-паттерн
3. Fallback на null с последующей обработкой

**Реализация:**
```python
def extract_json_from_string(text):
    """Извлекает JSON из строки, если модель добавила лишний текст."""
    try:
        return json.loads(text)
    except json.JSONDecodeError:
        match = re.search(r'\{.*\}|\[.*\]', text, re.DOTALL)
        if match:
            try:
                return json.loads(match.group(0))
            except:
                pass
    return None
```

**Результат:** Система корректно обрабатывает ~95% ответов LLM, включая случаи с "мусором" вокруг JSON.

### 1.3 [BUG-12] Fallback-задача при ошибках генерации плана

**Проблема:** При некорректном ответе LLM или ошибке парсинга проект создавался без задач - пользователь видел пустой экран.

**Решение:**
Добавлен fallback-механизм: если LLM не вернул валидный план, система создаёт одну дефолтную задачу с понятным названием.

**Реализация:**
```python
if not created:
    print("Plan generation failed or empty, creating default task.")
    default_task = Task(
        project_id=project.id, 
        title=f"Разобраться с проектом: {title}", 
        minutes=60
    )
    db.add(default_task)
    db.commit()
```

**Результат:** Пользователь всегда получает хотя бы одну задачу для старта, даже при проблемах с LLM.

### 1.4 [BUG-05, BUG-08] Feedback-сообщения после действий

**Проблема:** После выполнения задачи пользователи не получали никакого подтверждения. Персона P1 отметила: "Даже не поняла, сработало ли".

**Решение:**
Добавлены информативные сообщения после ключевых действий:
- "Great job!" - после выполнения задачи
- "Task simplified" - после декомпозиции
- "Project Created" - после загрузки проекта
- "Error reading document" - при ошибке парсинга

**Реализация:**
```python
return RedirectResponse(url="/?msg=Great+job!", status_code=303)
```

```html
{% if message %}
<div class="bg-blue-100 text-blue-800 p-3 rounded mb-4 text-sm">
    {{ message }}
</div>
{% endif %}
```

**Результат:** Пользователи получают мгновенную обратную связь, что создаёт ощущение прогресса.

### 1.5 [BUG-07] Редизайн UI с Tailwind CSS

**Проблема:** Персона P3 отметила: "Это финальная версия? Выглядит как прототип". UI без стилей снижал доверие к продукту.

**Решение:**
Редизайн интерфейса с использованием Tailwind CSS:
- Чистые карточки с тенью и скруглёнными углами
- Цветовое кодирование кнопок: зелёный для "Done", красный для "Сложно"
- Время выполнения отображается компактно (⏱ 30 мин)
- Название проекта - мелким шрифтом над задачей
- Консистентная типографика и отступы

**Результат:** Эвристическая оценка по критерию "Эстетика и минимализм" выросла с 2/5 до 4/5.

---

### 1.6 [BUG-13] Валидация формата файла на уровне UI

**Проблема:** Персона P4 загрузила .docx и получила непонятный crash. Пользователи могли загрузить любой файл, что приводило к ошибкам.

**Решение:**
Добавлена фильтрация на уровне HTML-формы, ограничивающая выбор файлов только PDF.

**Реализация:**
```html
<input type="file" name="file" accept=".pdf" class="hidden" id="file-upload">
```

**Результат:** Пользователи физически не могут выбрать неподдерживаемый файл в диалоге.

### 1.7 [TC-04] Обработка пустых документов

**Проблема:** Загрузка пустого или повреждённого PDF приводила к необработанному исключению (500 Error).

**Решение:**
Добавлена проверка результата парсинга документа с graceful redirect.

**Реализация:**
```python
rag_result = RAGService.process_document_and_extract_metadata(file_path)

if not rag_result:
    return RedirectResponse(url="/?msg=Error+reading+document", status_code=303)
```

**Результат:** Система корректно обрабатывает edge case с пустыми документами.

## 4. Выводы и рекомендации

Текущая итерация сфокусировалась на **устойчивости системы** (graceful degradation, парсинг JSON) и **базовом пользовательском опыте** (декомпозиция задач, feedback, визуальный дизайн). Это позволило сделать MVP функциональным для основного сценария использования.

**Критические проблемы, оставшиеся в backlog** (отсутствие онбординга и кнопки "Отложить"), должны быть приоритетом для следующей итерации, так как они напрямую влияют на retention пользователей.

**Рекомендация:** Перед добавлением новых функций (геймификация, фильтрация) необходимо закрыть оставшиеся критические баги.
